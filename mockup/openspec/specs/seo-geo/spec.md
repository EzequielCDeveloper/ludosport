# SEO + Geo Specification

## Purpose

The landing page MUST be discoverable by search engines and geographically targeted to Hermosillo, Sonora, MX through Metadata API, OpenGraph, geo tags, JSON-LD structured data, and standard SEO route files.

## Requirements

### Requirement: Metadata API

| Attribute | Value |
|-----------|-------|
| Priority | P0 |
| Server/Client | Server (layout export) |

The root layout MUST export a `metadata` object (or `generateMetadata`) with `title: "Ludo Sport Drake Academy — Esgrima con Sables de Madera"`, `description`, OpenGraph (title, description, images array, locale `es_MX`), and `lang="es"` on the `<html>` element.

#### Scenario: Title renders in document head

- GIVEN the page renders
- WHEN inspecting `<head>`
- THEN `<title>` contains the exact title string
- AND `<meta name="description">` is present
- AND `<meta property="og:locale">` is `es_MX`

#### Scenario: OpenGraph image fallback

- GIVEN no custom og:image is set
- THEN the default image or placeholder renders
- AND og:title and og:description match the metadata

### Requirement: Geo Meta Tags

| Attribute | Value |
|-----------|-------|
| Priority | P0 |
| Server/Client | Server |

The layout MUST include `<meta name="geo.region" content="MX-SON">` and `<meta name="geo.placename" content="Hermosillo">` via `metadata` or custom `<head>` injection.

#### Scenario: Geo tags present in head

- GIVEN the page renders
- WHEN inspecting `<head>`
- THEN `geo.region` equals `MX-SON`
- AND `geo.placename` equals `Hermosillo`

### Requirement: JSON-LD LocalBusiness

| Attribute | Value |
|-----------|-------|
| Priority | P0 |
| Server/Client | Server (JSON-LD script) |

The root layout MUST inject a JSON-LD `LocalBusiness` schema via `<script type="application/ld+json">` with `name`, `address` (Callejón Jalisco, entre Soto y Pesqueira, Hermosillo, Sonora), `telephone` (+526531649951), `areaServed` (Hermosillo, Sonora), and `url`. The schema MUST be generated by `lib/json-ld.ts`.

#### Scenario: JSON-LD renders in page source

- GIVEN the page renders
- WHEN viewing the HTML source
- THEN a `<script type="application/ld+json">` block exists
- AND `@type` is `LocalBusiness`
- AND `address.streetAddress` contains "Callejón Jalisco"
- AND `telephone` is `+526531649951`

### Requirement: Robots

| Attribute | Value |
|-----------|-------|
| Priority | P1 |

`app/robots.ts` MUST export a `Robots` object allowing all crawlers (`allow: "/"`) and referencing the sitemap URL.

#### Scenario: Robots allows all

- GIVEN a GET to `/robots.txt`
- THEN the response contains `Allow: /`
- AND `Sitemap:` points to the full sitemap URL

### Requirement: Sitemap

| Attribute | Value |
|-----------|-------|
| Priority | P1 |

`app/sitemap.ts` MUST export a `Sitemap` array with a single entry for the landing page URL and a `lastModified` date.

#### Scenario: Sitemap returns one entry

- GIVEN a GET to `/sitemap.xml`
- THEN the response is valid XML
- AND it contains exactly one `<url>` entry with `<loc>` pointing to the base URL

### Requirement: Security Headers

| Attribute | Value |
|-----------|-------|
| Priority | P1 |

`next.config.ts` MUST set `X-Content-Type-Options: nosniff` and `Referrer-Policy: strict-origin-when-cross-origin` via the `headers()` function.

#### Scenario: Security headers sent

- GIVEN an HTTP response to any page
- THEN `X-Content-Type-Options` header equals `nosniff`
- AND `Referrer-Policy` header equals `strict-origin-when-cross-origin`

### Requirement: Remote Images

| Attribute | Value |
|-----------|-------|
| Priority | P1 |

`next.config.ts` MUST configure `images.remotePatterns` with protocol `https`, hostname `placehold.co`.

#### Scenario: Remote image allowed

- GIVEN `next/image` renders a `placehold.co` URL
- THEN it does not throw an unconfigured host error
